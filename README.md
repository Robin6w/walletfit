# walletfit

## 지출 데이터 기반 카드 "조합" 추천 서비스

<p align="center">
  <strong>아주대학교 산업공학과 · 산업공학종합설계 팀 프로젝트</strong><br>
  카드 한 장을 추천하는 서비스는 많다. walletfit은 지갑 속 여러 카드의 <b>최적 조합</b>을 계산한다.
</p>

walletfit은 사용자의 카테고리별 월 지출액을 입력받아, 카드를 최대 K장까지 섞어 썼을 때 순혜택(총 혜택 − 연회비)이 가장 큰 조합과
카테고리별 결제 배분을 계산하는 클라이언트 전용 SPA입니다.

> 이 폴더(walletfit-ds)는 앱(walletfit-app)을 복사한 뒤 데이터 작업(DS) 결과를 모두 적용한 버전입니다.
> 화면은 **v2**(Claude Design 'WalletFit 디자인 개선' 양준서 페이지, 2026-10-29)이고, 10월 초 v1 화면은 `#/v1` 주소로 그대로 열 수 있습니다.
> 원래 앱 폴더(walletfit-app)는 그대로 두었습니다. 바뀐 점은 [v2 화면](#-v2-화면-2026-10-29)과 [v1에서 바뀐 것](#-v1에서-바뀐-것)에 정리했습니다.

## 🆕 v2 화면 (2026-10-29)

Claude Design 'WalletFit 디자인 개선'의 양준서 페이지를 `src/v2`에 옮겼습니다. 카드 사진을 빼면 크기·색·글꼴·문구는 디자인 원본(`.dc.html`) 값을 그대로 썼고, 카드가 나오는 곳에는 카드고릴라 실제 카드 사진을 넣었습니다(홈은 디자인 그림 그대로).

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `#/` | 두 갈래 시작, 저장한 지갑 요약 |
| 지갑 만들기 A(보유한 카드로) | `#/make/own/cards → spend → brands → result` | 카드 선택(실제 사진), 지출 입력, 자주 가는 곳, 추천 결과 |
| 명세서 경로 | `#/make/own/statement` | PDF(비밀번호 포함)·CSV·TXT. 여러 달이면 월평균, 브랜드 금액도 같이 읽음 |
| 여유 없이 다시 계산 | `#/make/own/result?margin=0` | 기본 추천과 나란히 비교 |
| 지갑 만들기 B(새 카드까지) | `#/make/new/type → … → result` | 새 카드가 가진 카드 조합보다 낫지 않으면 가진 카드 조합을 그대로 보여 줌 |
| 내 지갑 | `#/wallet` | 저장한 지갑(실적 막대, 결제 가이드, 할 일) / 빈 지갑 |
| 전체 카드 | `#/cards` | 검색·필터·정렬, 비교함(최대 3장) |
| 카드 비교 | `#/compare?ids=…` | 카드 한 장으로 지출 전부를 낼 때 금액, 알아 둘 점, 항목별 표(출시일·혜택 유지·전월실적·혜택·한도), 다른 점만 보기 |
| 혜택별 추천 | `#/benefit?cat=…` | 카테고리 하나 금액을 각 카드로 낼 때 받는 혜택(내 카드 / 발급 가능한 전체 카드) |
| 이용 가이드 | `#/guide` | |
| 카드 상담 | 어느 화면에서나 오른쪽 | 계산 엔진 결과로 답(카드별 혜택 표, 여유 없이 비교, 카드 비교). 아주LLM 키가 있으면 엔진 답을 다듬고, 정해진 유형 밖의 질문은 계산 기록·카드 혜택 표를 근거로 직접 답함(숫자는 기록에 있는 값만) |

정한 규칙(설계 문서 §10)
- 자주 가는 곳: 고른 브랜드가 카테고리 지출의 70%를 나눠 씀. 안 고른 카테고리는 계산기 기본값(브랜드 한 곳 35%, 묶음 70%). '없어요'는 브랜드 할인 0
- 결과 화면의 계산 근거·'숫자가 이상해요'는 '더 자세히 보고 싶다면' 안에 디자인과 같은 모양으로 둠
- 계산 조건(디자인에 없는 기능)은 히어로 바로 아래 '계산 조건' 띠에 지금 조건을 한 줄로 보여 주고, '조건 바꾸기'로 그 자리에서 펼침(2026-10-29). 칩·세그먼트·셀렉트는 디자인의 전체 카드 필터와 같은 모양. 안에 '월 소득으로 지출 채우기'(v1 소득 추정 부품을 v2 모양으로 새로 만듦, 카드 수는 결과 화면과 같은 조건·브랜드 비중으로 계산)와 '카드 바꿔보기'
- 카드 비교의 '○○까지 넣어서 지갑 다시 짜기'는 그 카드를 꼭 넣고(조건 `pinned`) 새 카드 추천을 다시 계산함. 조건 바꾸기에서 뺄 수 있음
- 카드고릴라 혜택 요약만 읽은 카드(auto)는 실적 조건을 '확인 전'으로 표시하고, 금액이 크게 나올 수 있다고 알림

엔진(wf_engine.py)에 더한 값(계산은 그대로, 화면용 값만 추가)
- 카드 결과: `choiceGroups`(패키지 자동 여부), `cardType`, 전월실적 `excludedItems`·`excludedCats`·`grace`(신규 발급 유예)
- 혜택 결과: `sharedIds`(묶음 한도), `region`·`channel`·`condition`(결제 조건), `perTxnCap`·`minTxn`·`countLimits`, `valueTiers`·`capTiers`
- 카드 수 막대 `bar[].sids`
- 혜택별 추천 `categoryRank`: 패키지형 카드는 그 카테고리 혜택이 가장 큰 패키지로 계산(`switched`), 한 줄 설명 재료 `detail`(걸린 한도, 건당·횟수 조건, 브랜드 비중)

새 데이터
- `data/catalog/card-meta.json`: 카드고릴라 원문에서 뽑은 출시일(540장)·혜택 유지 기간(632장). `npx tsx scripts/buildCardMeta.ts`로 다시 만듦
- `public/samples/walletfit-sample-statement.csv`: 명세서 화면 '예시 파일로 해 보기'용 가상 명세서(개인 정보 없음)
- `public/brands/`: 디자인 캔버스의 브랜드 로고

엔진 고도화 때 볼 것(화면에서는 보호 장치로 막아 둠)
1. 실적 여유 없이(margin 0) 추천이 여유 2만원 대안보다 낮게 나오는 경우가 있음(31,674 < 35,533). 화면은 {여유 없이 추천, 대안 조합, 기본 조합}을 여유 없이 다시 계산해 가장 큰 것을 씀(`model/guards.ts` pickNoMargin)
2. 새 카드 흐름 결과가 가진 카드만 쓸 때보다 낮게 나오는 경우가 있음(32,681 < 33,422, 후보 12장 추리기에서 D4가 빠지는 것으로 보임). 화면은 가진 카드 조합을 그대로 보여 줌(pickNewFlow)
3. 카드 수 막대가 장수가 늘 때 줄어드는 경우가 있어 앞 장수 값 이상으로 맞춤(monotoneBar)
4. 전체 카드 '내 지출에 유리한 순'에서 혜택 요약만 읽은 카드가 실제보다 크게 나와 위로 올라옴
5. 브라우저(Pyodide)와 CPython의 배분이 순혜택이 같은 다른 해로 갈리는 경우가 있음

검증: `npm run build` 통과, Vitest 258개 통과, `scripts/testEngine.py` 14개 통과, oxlint 오류 0, 모든 화면 390·768·1440px에서 가로 넘침과 콘솔 오류 없음.

### 2026-10-29 개선(점검 목록 5~19번, 프로젝트 문서 `walletfit-v2-improvements-2026-10-29.md`)
속도
- 결과 화면 첫 계산에서 대안 조합(`withAlt`)을 뺐다. 대안은 '여유 없이 다시 계산' 화면과 상담에서 필요할 때 엔진 `alt`(새 함수 `alt_json`)로 따로 계산한다
- 3장 이상 MILP 시간 제한 5초 → 2초(`K3_TIME_LIMIT`). 지출 조건 11가지에서 결과 금액이 모두 같았다
- v1 계산 코드(walletOptimizerCore.py)는 v1 화면이 요청할 때만 불러오고, milp.py는 scipy를 처음 풀 때 불러온다. 준비가 끝나면 한가할 때 scipy를 미리 불러 둔다. calc.py만 쓰는 rank·categoryRank는 약 2초 빨리 시작한다
- 최근 조합 찾기 결과 8개를 브라우저(localStorage `walletfit:v2:engine-results`)에 남긴다. 버전은 엔진 py·혜택 표 파일의 빌드 해시(`engineVersion.ts`)라서 엔진이나 데이터가 바뀌면 버린다. 개발 서버에서는 남기지 않는다
- 결과 기다리는 화면: '계산 엔진 준비 → 조합 계산' 두 단계와 경과 시간
- 측정(헤드리스, 6장): 조합 계산 12.8초 → 약 6.6초, 처음부터 단계를 밟는 흐름에서 '추천 조합 보기' 후 9.1초 → 6.1초, 새로고침 뒤 같은 입력 약 21초 → 0.7초
- 엔진 미리 띄우기는 지갑 만들기·전체 카드·비교·혜택별 추천에 들어갈 때(또는 상담 창을 열 때) 시작한다. 홈·이용 가이드·내 지갑만 보면 엔진 파일(약 36MB)을 내려받지 않고, 데이터 절약 모드면 계산할 때 띄운다

화면
- 전체 카드: 지출이 없으면 '원문 확인 카드 먼저'(새 정렬) 순서. '내 지출에 유리한 순'이면 타일에 '내 지출로 연회비 빼고 월 약 ○원'과, 요약 기반 카드는 '혜택 요약으로 낸 추정값'
- 혜택별 추천: 내 카드에 그 혜택이 없으면 0원 순위 대신 '발급 가능한 전체 카드 보기' 버튼
- 알림: 넓은 화면은 머리줄 아래 가운데, 좁은 화면은 아래쪽 가운데(`ToastProvider placement`)
- 단계 표시: 좁은 화면에서 현재 단계로 자동 스크롤, 요약(· 6장)은 좁은 화면과 상담 창을 연 화면에서 숨김
- 히어로 차액은 화면에 보이는 천 원 단위 값끼리 뺀다(25,000원·33,000원 → '8천원')
- 그 밖의 지출을 모두 한 카드로 내면 '모두 TEN으로 결제하고, 통신비는 자동납부로 걸어 두세요'
- 카드 선택 첫 목록: 담은 카드 → 원문 확인 카드 → 나머지 최신순 → 발급 중단

접근성·문구·번들
- 테두리 안 입력 칸(지출 금액, 혜택 금액, 카드 검색, 상담 입력)에 포커스 표시(`.w-field`, `.w-field-strong`)
- 색 대비: 홈 파란 띠 글자 #E3EAFF, 비교 화면 수집일 #56658E. 장식용 카드 그림 속 글자 2곳은 aria-hidden이라 그대로 둠
- 카드 바꿔보기 조사('을(를)' → 카드 이름에 맞춰), 수집일 표기 통일(혜택 9월 17일, 출시일 9월 28일), 결과 화면 소득 추정 안내 문구
- 글꼴을 CSS에 base64로 넣지 않음: CSS 460KB → 370KB(압축 160KB → 98KB)
- 그대로 둔 것: 홈에서 카드 목록 청크(압축 106KB)가 로드되는 것(상담 창·카드 그림 구조를 바꿔야 해서), v1 코드

검증: Vitest 263개, `scripts/testEngine.py` 14개, `npm run build` 통과. 1440·390px 14개 화면 가로 넘침·콘솔 오류 없음, axe 검사 위반은 장식용 카드 그림 2곳뿐, Tab 이동 모든 칸에 포커스 표시.

| extracted | 5 | AI 추출 + 원문 대조 통과 (`extracted_scn`) | 계산 근거에 '원문 대조 통과, 사람 검수 전' |
| auto | 1,458 | 카탈로그 혜택 요약·구간표를 혜택 표 형식으로 자동 변환 | 계산 근거에 '카드 혜택 요약 문구로 계산(원문 대조 전)' |

auto 카드의 숫자 정확도는 이전 정규식 파서 수준입니다(52장 평가 기준 금액 ±5% 안 12%). 한도도 요율로 추정한 값이라 실제보다 높게 나오는 카드가 있습니다.
혜택 표를 AI 추출로 바꾸면(`1_혜택정보구조화/prompts/extract_v2.md`) `npm run build:benefit`만 다시 돌리면 됩니다.

### 정한 규칙
- 실적 여유 기본 2만원
- 브랜드 금액을 비운 카테고리는 브랜드 할인 대상을 지출의 35%로 추정하고 '추정' 표시
- 통신비·대중교통은 카드 1장에만 배정(자동납부·후불교통은 카드 1장에만 등록됨)
- 카드 장수는 기존 두 모드 유지: 혜택 최대화(최대 카드 수 안에서 순혜택 최대) / 효율적(1등 카드 순혜택의 30% 미만을 버는 카드 제외)
- 새 카드까지 포함한 추천에서는 발급 대상이 정해진 카드(나라사랑, 국민행복, 청소년, 선불 등)를 뺌

## ✨ 주요 기능

0. **홈**: "보유한 카드로" / "새 카드까지 포함해서" 두 갈래로 지갑 만들기를 시작하고, 저장한 지갑이 있으면 요약을 보여줍니다.
1. **지갑 만들기 (카드 선택 → 지출 입력 → 자주 가는 곳 → 추천 결과)**
   - **카드 선택**: 카드명·카드사·한글 별명(탭탭오, 미스터라이프 등)으로 찾고, 담은 카드마다 혜택 표에서 읽은 혜택과 실적 조건을 바로 보여줍니다. 발급이 끝난 카드도 담을 수 있습니다.
   - **지출 입력**: 카테고리별 월 금액. 명세서나 월 소득으로 대략 채울 수 있습니다.
   - **자주 가는 곳**: 담은 카드에 브랜드 한정 할인(스타벅스, GS25 등)이 있는 카테고리만 브랜드별 금액을 묻습니다. 비우면 35%로 추정합니다.
   - **추천 결과**: 헤드라인, 월 혜택 − 연회비 = 순혜택, 카드별 실적 막대(할인받아 실적에서 빠지는 결제 포함), 카드별 역할(원문 한도 기준 혜택 행), 결제 가이드(혜택 없는 지출을 어느 카드로 낼지 포함), 카드사 앱에서 할 일, 카드 수 막대(1~5장), 실적 여유·연회비 상한, 이 계산에 쓴 값.
   - **계산 근거**: 패키지 비교 → 전월실적 → 혜택별 계산 → 묶음 한도 → 합계. 원문 보기, '숫자가 이상해요' 신고(브라우저에 검수 목록으로 저장).
   - **조건 바꾸기**: 혜택 최대화/효율적, 최대 카드 수, 카드 종류, 카드사 제외, 소득으로 카드 수 추정, 카드 바꿔보기.
2. **내 지갑**: 저장한 조합, 카드별 실적 여유, 결제 순서, 할 일 체크리스트, 이번 조합에서 쓰지 않는 카드.
3. **전체 카드**: 1,525장 검색·필터, 내 지출에 유리한 순 정렬(새 계산기), 내 카드 담기, 최대 3장 비교, 카드 상세.
4. **혜택별 추천**: 한 카테고리 금액을 각 카드로 낼 때 받는 혜택 순위(발급 가능한 전체 카드 / 내 카드), 카드마다 계산 근거.
5. **명세서 분석**: 결제 문자, 영수증 이미지, PDF 명세서를 브라우저 안에서 읽어 카테고리별 지출을 채우고, 가맹점 이름이 혜택 표의 브랜드와 맞으면 '자주 가는 곳' 금액도 같이 채웁니다.
6. **카드 상담**: 추천 결과의 숫자와 배분 이유를 계산 기록 그대로 설명하고, 실적 여유를 바꿔 다시 계산하는 버튼을 줍니다. `.env`에 아주LLM 게이트웨이를 넣고 화면에서 API Key를 등록하면 아주LLM이 답하고, 표·버튼은 계산 기록에서 만듭니다.

## 🔄 카드 카탈로그 자동 수집
1. **`npm run fetch:catalog`** — 카드고릴라 상세 페이지의 `application/ld+json`으로 카드명·카드사·연회비·이미지·혜택 요약·발급 중단 여부를 `cards-catalog.json`에 모읍니다.
2. **`npm run fetch:tiers`** — 카드고릴라 내부 API 원본을 `cards-detail-raw.json`에 저장합니다. 일부 클라우드 IP에서 막혀 있어 사용자 컴퓨터에서 실행해야 합니다.
3. **`npm run build:catalog`** — 원본 구간표로 `cards-catalog.json`에 구간별 요율을 채웁니다.
4. **`npm run build:benefit`** (v1) — 정답표·AI 추출 혜택 표가 있는 카드는 그 표를, 나머지는 위 카탈로그를 자동 변환해서 `cards-benefit.json`을 만듭니다.

카드고릴라 이용약관을 정기적으로 확인하고, 과도한 요청은 피해주세요.

## ⚡️ 성능 최적화
1. 검색 디바운스(250ms), 페이지별 지연 로드(React.lazy), 카탈로그 JSON 청크 분리는 기존과 같습니다.
2. **계산은 전부 Web Worker**: 혜택 표 1,525장 정렬 계산은 브라우저에서 약 0.5초, 보유 카드 6장 조합은 약 6~7초(카드 수 1~3장을 차례로 풀고, 더 늘지 않으면 멈춤. 3장 이상은 시간 제한 2초).
3. **후보 추리기**: 새 카드까지 포함하면 카드 한 장 계산값 상위 8장 + 카테고리별 상위 2장(최대 12장)만 MILP에 넣습니다. 8장 이하일 때만 카테고리를 나눠 결제하는 모드로 풉니다.
4. 엔진은 엔진을 쓰는 화면(지갑 만들기·전체 카드·비교·혜택별 추천)에 들어오면 미리 부팅합니다. 최근 조합 결과 8개는 브라우저에 남겨 새로고침 뒤에도 바로 보여 줍니다.

> 자세한 전/후 벤치마크는 [성능 최적화 보고서](docs/performance-optimization.md)에 있습니다(v1 이전 기준).

서버가 필요 없는 정적 SPA라서 `npm run build`가 만드는 `dist/`만 올리면 됩니다.

- `public/pyodide-dist/`(약 90MB, scipy wheel 하나가 약 47MB)와 `cards-benefit.json`(3MB, gzip 250KB)이 함께 배포됩니다. Vercel Hobby CLI 업로드 한도(100MB)에 가까우니 Git 연결 배포나 Git LFS를 검토하세요.
- 아주LLM 상담을 쓰려면 배포 환경변수에 `VITE_AZU_LLM_BASE_URL`, `VITE_AZU_LLM_MODEL`을 넣습니다(빌드할 때 들어가므로 넣은 뒤 다시 배포). 값은 로컬 `.env`와 같습니다. API 키는 방문자가 상담 창의 '아주LLM 연결하기'에서 넣고 그 브라우저에만 저장됩니다. 게이트웨이가 배포 주소에서 오는 요청을 막으면(CORS) 상담은 계산 결과 답으로 돌아갑니다.
- 데이터 작업(DS) 폴더(`1_혜택정보구조화/`, `1-2_추천엔진/`, `2_지출추정/`, `demo/`, `v1_최종디자인/`)는 저장소에 올리지 않고 로컬 walletfit-ds에만 둡니다(`.gitignore`).
- 카드 이미지는 아직 카드고릴라 CDN 주소를 씁니다. 못 불러오면 색 상자 + 카드 이름으로 대신 보여줍니다.
- 브랜치/커밋 규칙은 `.cursorrules`에 있습니다. `main`에 직접 커밋하지 않고, 에이전트는 승인 없이 커밋·푸시하지 않습니다.

- 앱에 들어간 엔진 파일과 원본의 관계
  - `calc.py`: 원본은 `1_혜택정보구조화/calc.py`. `npm run build:benefit`이 앱 쪽 사본을 맞춥니다. 이번에 Pyodide의 numpy 1.26에서도 돌도록 `np.trapezoid`를 `trapz`와 둘 다 받게 고쳤습니다.
  - `milp.py`: 원본은 `1-2_추천엔진/milp.py`. 앱 쪽 사본에는 사용자 브랜드 금액(`user_brand_share`), 시간대 한정 혜택(`scope.hours`), 통신비·대중교통 통째 배정(`whole_cats`)을 더했습니다.
- 시안(v1_최종디자인)의 숫자는 조합 탐색 시안(combo.py) 결과(D4 + taptap O, 월 33,357원)입니다. 앱은 추천 엔진 v2로 더 나은 조합(같은 시나리오에서 D4 + iD ON, 약 3만 4천원)을 찾아서 화면 숫자가 시안과 다릅니다. 두 숫자 모두 calc.py로 다시 계산한 값입니다.
- 카드 명세서 PDF 같은 개인정보 파일은 이 폴더와 저장소에 넣지 않습니다.
